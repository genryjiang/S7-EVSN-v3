# ISO 26262 Readiness

Use this skill for safety-readiness work and evidence preservation. This skill does not establish compliance.

## Core Guidance

- Do not claim ISO 26262 compliance.
- Treat this as readiness and evidence-preservation guidance only.
- Encourage traceable requirements IDs where available.
- Preserve safety assumptions, design rationale, failure behavior, diagnostic behavior, and verification evidence.
- Identify when a change needs safety review, deviation record, test evidence, or requirements update.
- Separate facts, assumptions, open risks, and required approvals.
- Keep hardware-software interface assumptions explicit, including units, ranges, timing, ownership, validity, diagnostics, and fallback behavior.
- Link verification evidence to the behavior or requirement it supports.
